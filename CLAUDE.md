# Yacht Lead-Gen Portal

Static lead-gen site: premium yachts, 5 brands, a network of hundreds
of showrooms, leads routed to dealers via Pipedrive. Product
priorities: SEO, premium visual quality, media performance.

Details on demand: `docs/backlog-mvp.md` (work plan),
`docs/kontrakt-api-lead.md` (lead endpoint contract),
`docs/kontrakt-locations.md` (locations data contract),
`README-CONTENT.md` (content delivery format, Polish — binds the
content team), `docs/design-handoff/` (visual reference, read-only).

## Principles

1. **Think before coding** — read the existing pattern before writing
   your own. Search the repo for a similar implementation first.
2. **Simplicity first** — the minimum complexity needed for the
   current task. No abstractions or "future-proofing".
3. **Surgical changes** — change only what's needed. No refactoring
   of surrounding code, no drive-by fixes.
4. **Ship static** — the default output is HTML with zero JS.
   Interactivity requires justification.

## Tech Stack

- **App:** Astro (static output) + React islands, TypeScript strict
- **Styling:** Tailwind v4, tokens in `@theme` (`src/styles/global.css`)
- **Content:** content collections (Zod) + `src/data/locations.json`
- **CMS:** Sanity — blog (pl/en) + notificationRecipients singleton;
  Studio mounted as `/admin` route (client:only, noindex)
- **Integrations:** Pipedrive (CRM), Resend (email), Turnstile
  (antispam), Mux (video), Mapbox GL (network page only), GA4 with
  Consent Mode v2
- **Infra:** Vercel (static + serverless endpoints) via GitHub integration.
  No database, no workers, no separate backend service.
  @astrojs/vercel adapter added locally in step 5 (API routes).
- **i18n:** en (default) / pl / es / it / ru, prefixDefaultLocale, localized slugs

## Structure

```
src/pages/        routing [lang]/... + api/ (serverless endpoints)
src/layouts/
src/components/   Astro — sections and ui, static, zero client JS
src/islands/      React — filter, lead-form, compare, network-map
src/content/      collections: yachts, brands, dealers
src/data/         locations.json (generated by import script)
src/lib/          isomorphic helpers (i18n, images, seo)
src/lib/server/   SERVER ONLY: pipedrive, resend, turnstile, sanity
src/styles/       global.css with @theme — single source of truth for tokens
scripts/          import-locations (CSV -> JSON + geocoding)
docs/             backlog, contracts, design-handoff/
```

## NEVER

- Never commit/push without `build` + `typecheck` passing locally
- Never import from `src/lib/server/` into components, islands, or
  anything that ends up in the client bundle
- Never add `client:*` without justification in the PR description;
  islands live only in `src/islands/`
- Never change the content format (`src/content/`, image naming
  conventions in `src/assets/`, locations.json format) — these are
  external APIs with the people delivering data; changes require user
  approval and are NOT refactoring
- Never "normalize" `pipedriveOptionLabel` — it must match the option
  label configured in Pipedrive character-for-character
- Never hardcode email recipients — the endpoint reads them from
  Sanity at request time
- Never render a language fallback — a missing locale version means
  the page does not exist
- Never hardcode colors/spacing/fonts — tokens from `@theme` only
- Never add UI component libraries (shadcn etc.) or new npm
  dependencies without justification in the PR
- Never fire analytics beacons before consent (Consent Mode v2)
- Never put secrets outside env; only `PUBLIC_`-prefixed variables
  may reach the client bundle

## Do NOT Modify Without Explicit Instruction

- `src/styles/global.css` `@theme` section — tokens cascade everywhere
- Collection schemas in terms of fields and semantics (code shape is
  fine to change)
- `docs/design-handoff/` — historical reference, read-only
- `scripts/import-locations` input/output format

## Definition of Done

**New page:** 5 locale versions (en/pl/es/it/ru — or missing content explicitly noted)
+ meta title/description + hreflang + images via astro:assets
+ Lighthouse mobile >= 95 not regressed (landing/brand/yacht)
**New island:** justification in PR + `client:visible` (other
directives need separate justification) + data passed as build-time
props, no client fetching
**Endpoint change:** Zod validation shared with the client + unit test
for logic in `src/lib/server/` (Vitest) + integration failure paths
never lose a lead
**Content/schema change:** build validates (build error, not silent
fallback) + user approval if an external format is affected

## Testing

Vitest for logic in `src/lib/server/` and `scripts/`. Bugfix = write
a reproducing test first. Static pages: `astro check` + build as the
gate, no snapshot tests.

## Escalation

Product decisions, changes to external contracts, ambiguity in the
brief = ask the user BEFORE writing code. User = architect and
reviewer; one backlog step = one PR.

## When Compacting Context

Preserve: list of modified files, current backlog step, any violated
rule from this file, open questions for the user.
